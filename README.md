## Our working rhythm

**Before building:** open a task, agree on what done means, and pick an owner. Keep each task small enough to demonstrate within a week.

**After a work session:** open a work log with evidence, what you learned, and the next step. Link the task so the story stays connected.

**When you need input:** open a mentor review with a specific question. Either person can comment, attach screenshots, suggest an approach, or link a pull request.

**Once a week:** review blockers together, celebrate one concrete outcome, and choose the next one to three tasks. Capture decisions in meeting notes.

## A simple tracking system

| Label | Meaning |
| :--- | :--- |
| `status:next` | Ready to pick up |
| `status:doing` | Someone is actively working on it |
| `status:blocked` | Needs help or a dependency |
| `status:review` | Ready for feedback |
| Closed issue | Finished, with evidence linked; or closed with a reason |

Use **one status label per open task** and assign the person taking the next action. Work logs and ideas do not need status labels. The dashboard flags tasks with conflicting or missing statuses. There is no need to maintain a second task list.
